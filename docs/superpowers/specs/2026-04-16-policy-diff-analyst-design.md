**Date**: 2026-04-16
**Author**: carykwok (with Claude)
**Status**: Draft — pending user review

---

## 1. 背景与目标

### 1.1 问题
资深分析师研读政府工作报告等重要政策文件时，核心工作是三件事：
1. **定基调**（宏观方向）—— 判断保增长 vs 防风险
2. **找主线**（产业机会）—— 识别本年度重点扶持赛道
3. **识风险**（避雷方向）—— 抓住监管收紧/政策承压领域

目前这件事全靠人工逐字比对+记忆调用，痛点：
- **颗粒度难兼顾**：盯细节容易漏主线，盯主线容易漏措辞信号
- **历史对照成本高**：跨年度、跨文件互证需要反复翻阅
- **产出零散**：分析过程和交付物（文章、图表、数据表）割裂，需要二次整理

### 1.2 目标
构建一个 Claude Code skill `policy-diff-analyst`，能够：
- **两种使用模式**：
  - **Mode A**（用户直给）：支持粘贴文本、URL、PDF、Word 四种输入形态
  - **Mode B**（意图驱动，关键能力）：用户说"对比最新/近三年 XX 政策"，skill 自动从权威信源白名单（政府网、新华社等）抓取对应文件
- 按 MECE 框架做 **6 层分析维度 × 3 种对比方法**，产出 **3 件套交付物**（市场风格/行业配置/交易节奏）
- 交付物形态：一份 Word 分析文章（3 种风格可选）+ 一份 Excel 关键数据表 + 一个独立 charts 文件夹（6 类 PNG 图表）
- 首发范围：**政府工作报告**一类跑通闭环，后续逐个扩展到中央经济工作会议公报、五年规划纲要、三中全会决定、央行货币政策执行报告、部委专项政策

### 1.3 非目标（明确不做）
- 不做实时政策监控/推送
- 不做跨语言翻译（仅中文政策文件）
- 不做投资决策自动执行（仅产出分析建议，交易决策由人做）
- 不做自动爬取（URL 输入时由 skill 抓取，但不做定时任务）
- 第一版不做历史回测（B3 历史映射方法论保留接口，实际回测能力放 v2）

## 2. 用户画像与使用场景

- **主用户**：carykwok（分析师/投研背景），有写文章和做图表的需求
- **典型场景 1**：两会结束次日，把新版政府工作报告 URL 和上年版 URL 喂给 skill，20 分钟内拿到一份媒体派风格的深度分析文 + 数据表 + 图表
- **典型场景 2**：中央经济工作会议公报发布后，做 CEWC 的跨年对比，输出投研派文章供团队传阅
- **典型场景 3**：研究五年规划时，把十四五纲要和十三五纲要的 PDF 丢进来，做战略级对比

## 3. 核心分析框架（MECE 三层）

### 3.1 A 层 — 分析维度（看什么）

| # | 维度 | 核心问题 | 抓手示例 |
|---|------|---------|---------|
| A1 | 宏观定调 | 保增长 vs 防风险？ | GDP 目标、赤字率、CPI 目标、城镇就业、形势判断定性句、总体基调词 |
| A2 | 政策工具 | 钱从哪来？ | 货币（稳健/灵活适度/精准有力、降准降息、结构性工具）、财政（赤字率、专项债、超长期特别国债） |
| A3 | 产业地图 | 钱去哪儿？ | 科技（AI/算力/半导体）、制造（新能源/智能制造）、安全（能源/粮食/供应链）、消费（汽车/地产/服务消费） |
| A4 | 风险监管 | 哪里不能碰？ | 房地产表述、地方债务、金融风险、平台经济监管松紧 |
| A5 | 民生分配 | 钱流向居民吗？ | 收入增长、社保医保、生育政策、教育医疗投入 |
| A6 | 区域/对外 | 空间与国际维度 | 区域协调（长三角/粤港澳/东北等）、对外开放、涉外表述（对美/一带一路） |
| A7 | 结构增量（横切视角） | 真正的新信息 | 新增提法 / 消失提法 / 升降调 / 表述顺序变化 |

> **设计说明**：A7 是横切前 6 层的"增量视角"，不与 A1-A6 并列——它回答的是"两版之间到底哪些是真增量"。

### 3.2 B 层 — 对比方法（怎么比）

| # | 方法 | 输出物 |
|---|------|-------|
| B1 | 定性 diff | 增/删/改/保四类表述清单，按 A1-A6 分层 |
| B2 | 定量统计 | 关键词词频对比表、6 维政策强度打分（0-5 分） |
| B3 | 历史映射 | 多版本趋势线（v1 预留接口；实际回测 v2 再做） |

### 3.3 C 层 — 交付产出（输出什么）

| # | 产出 | 颗粒度 |
|---|------|-------|
| C1 | 市场风格判断 | 成长/价值、内需/外需、进攻/防守 |
| C2 | 行业配置建议 | 超配/标配/低配 + 赛道清单 + 置信度标注 |
| C3 | 交易节奏判断 | 政策预期期（先涨）/ 落地期（分化）/ 兑现期 |

## 5. 输入规范

### 5.1 两种使用模式

#### Mode A — 显式输入（用户提供文件）
用户直接提供两份文件的具体来源：
- **(a) 直接粘贴文本**：两段文本作为 prompt 的一部分
- **(b) URL**：skill 抓取网页并提取正文
- **(c) PDF 文件路径**：本地 PDF 解析
- **(d) Word 文件路径**：本地 .docx 解析

#### Mode B — 意图驱动（skill 自动检索信源）⭐
用户描述意图，skill 自动从**信源白名单**抓取对应文件。典型 prompt：
- "帮我对比最新两版政府工作报告"
- "对比近三年的政府工作报告，做趋势分析"
- "把 2024 和 2023 的中央经济工作会议公报对齐一下"

Mode B 触发后，skill 的执行顺序是：
1. 解析用户意图 → 确定文件类型、版本数量、时间范围
2. 查询 `source_registry.py` → 拿到权威信源 URL 模板
3. 按白名单优先级抓取（主源失败 fallback 备源）
4. 向用户**展示将要抓取的 URL 清单**等待确认（owner 意识，避免乱抓）
5. 确认后开始抓取 → 进入正常分析流程

> **关键设计**：Mode B 默认支持 **2 版对比**（最新 vs 上一版）与 **N 版趋势**（近 N 年）。当 N>2 时，两两生成 diff + 一份总趋势分析文章。

### 5.2 Skill 交互协议
Skill 由用户 prompt 触发（非函数调用），SKILL.md 需引导 Claude 先识别 **Mode A / Mode B**，再按模式追问补齐：

| 信息 | Mode A 必需 | Mode B 必需 | 默认 | 示例 prompt 片段 |
|------|:----------:|:----------:|-----|----------------|
| 新版文件 | ✅ | — | — | "新版是这个 URL..." / "/path/to/2024.pdf" |
| 上一版文件 | ✅ | — | — | "旧版是..." |
| 意图描述 | — | ✅ | — | "对比最新两版" / "近三年趋势" |
| 文件类型 | ✅ | ✅ | v1 默认 `govt_work_report` | "政府工作报告" |
| 对比版本数 | — | ✅ | 2（最新 vs 上一版） | "近三年" → 3 |
| 文章风格 | ✅ | ✅ | 无默认，未指定时追问 | "投研派" / "通俗点"（→ retail） |
| 输出目录 | ❌ | ❌ | `./output/` | "输出到 ~/Desktop/policy2024/" |

当用户 prompt 信息不全，SKILL.md 指导 Claude **先追问补齐**再开干，避免 assume。
Mode B 在抓取前**必须**展示 URL 清单待用户确认。

### 5.3 信源白名单（Mode B 专用）

按可信度分层，主源优先，主源失败 fallback 备源：

| 文件类型 | 主源（Tier 1） | 备源（Tier 2） | URL 模板/索引策略 |
|---------|--------------|--------------|-----------------|
| 政府工作报告 | www.gov.cn（中国政府网） | 新华社 news.cn、人民网 people.com.cn | 年度检索：`政府工作报告 {year}` 定位正式发布页 |
| 中央经济工作会议公报 | www.gov.cn、新华社 | 人民日报、央视网 | 年度检索：`中央经济工作会议 {year}` |
| 五年规划纲要 | www.gov.cn | 新华社 | 整文 PDF 下载链接 |
| 三中全会决定 | www.gov.cn、新华社 | 人民日报 | 会议名+年份检索 |
| 央行货币政策执行报告 | 中国人民银行官网 pbc.gov.cn | — | 季度执行报告固定路径 |
| 部委专项政策 | 对应部委官网（发改委/工信部等） | www.gov.cn 转发页 | 部委名+政策名检索 |

**信源策略关键约束**：
- 仅访问白名单域名，SKILL.md 硬编码允许列表，**防止 prompt injection** 诱导 skill 抓取非权威源
- 抓取时 User-Agent 明示身份，遵守 robots.txt
- 结果缓存到 `cache/`（按文件类型+年份命名），避免重复抓取
- 历史版本索引策略：先查缓存 → 未命中走 Tier 1 → 失败 fallback Tier 2 → 全失败明确报错并提示用户走 Mode A

## 6. 输出规范

### 6.1 输出目录结构

**2 版对比（默认）**：
```
output/
├── report.docx              # 主分析文章（用户指定风格，正文不嵌入图）
├── data.xlsx                # 关键数据表（多 sheet：指标/词频/打分/差异）
└── charts/                  # 图片独立文件夹
    ├── G1_词频对比.png
    ├── G2_政策强度雷达.png
    ├── G3_行业配置矩阵.png
    ├── G4_指标历史曲线.png
    ├── G5_产业地图.png
    └── G6_措辞流向.png
```

**N 版趋势分析（Mode B 多版本）**：
```
output/
├── report_trend.docx        # 总趋势分析文章（首末对比 + 滚动相邻对比综合）
├── data.xlsx                # 所有版本汇总数据表
└── charts/
    ├── G1_词频趋势_YYYY-YYYY.png   # 多年度词频走势
    ├── G2_强度雷达_YYYY-YYYY.png   # 多年度叠加雷达
    ├── G4_指标历史曲线.png         # N 年曲线（N 版场景最有价值）
    └── ...（其余图按需生成）
```

> **关键决策**：图表**不默认嵌入 Word**，独立放 `charts/` 文件夹，方便用户在写二次稿、发公众号时按需取用。

### 6.2 三种文章风格

| 风格 | 定位 | 语言特征 | 结构模板 |
|------|------|---------|---------|
| `research`（投研派） | 券商分析师研报 | 严谨、结构化、术语密度高 | 摘要→结论→分维度论证→风险提示→附录 |
| `media`（媒体派） | 《财经》杂志深度风 | 叙事性、可读性强、有观察视角 | 开篇场景→深度解读→观点抛出→延展思考 |
| `retail`（投资派） | 大白话降维版 | 轻松、口语化、类比生动 | 一句话结论→掰开揉碎讲→划重点→操作提示 |

三种风格的 prompt 模板放在 `assets/style_*.md`。

### 6.3 六类图表

| # | 图表 | 服务维度 | 技术实现 |
|---|------|---------|---------|
| G1 | 词频对比柱状图（Top-20 新旧对比） | A7 结构增量 | matplotlib |
| G2 | 政策强度雷达图（6 维打分） | B2 定量 | matplotlib radar |
| G3 | 行业配置矩阵（超/标/低配 × 确定性） | C2 配置 | matplotlib heatmap |
| G4 | 关键指标历史曲线（GDP/赤字率/CPI 等） | A1 | matplotlib line |
| G5 | 产业地图树状图（赛道层级） | A3 | plotly sunburst |
| G6 | 措辞升降调流向图（增/删/升/降 sankey） | A7 | plotly sankey |

### 6.4 Excel 数据表结构
- `sheet1_指标对比`：A1 层量化指标新旧对照
- `sheet2_词频统计`：Top-50 高频词新旧对比
- `sheet3_政策强度`：6 维打分矩阵
- `sheet4_差异清单`：按 A1-A7 分层的定性 diff 条目

## 7. 架构设计（方案 B：主 skill + 子模块）

### 7.1 目录结构
```
policy-diff-analyst/
├── SKILL.md                    # 主流程入口（≤500 行）
├── scripts/
│   ├── source_registry.py      # [Mode B] 信源白名单 + URL 模板
│   ├── fetcher.py              # [Mode B] 按白名单抓取（含缓存）
│   ├── parse_input.py          # URL/PDF/Word/粘贴文本 → 结构化文本
│   ├── diff_engine.py          # A1-A7 六层对比核心
│   ├── score_model.py          # B2 定量打分
│   ├── build_charts.py         # G1-G6 六类图 → PNG
│   ├── build_docx.py           # Word 文章生成
│   └── build_xlsx.py           # Excel 数据表
├── references/
│   ├── profile_govt_work_report.md    # v1 首发 profile
│   └── source_whitelist.md            # 信源白名单说明文档
├── assets/
│   ├── style_research.md       # 投研派写作指南
│   ├── style_media.md          # 媒体派写作指南
│   ├── style_retail.md         # 投资派写作指南
│   └── docx_template.docx      # Word 样式模板
├── cache/                      # [Mode B] 抓取结果缓存（gitignore）
└── evals/
    └── evals.json              # 测试用例（历年两会报告对比）
```

### 7.2 执行流程
```
用户调用 skill
    ↓
SKILL.md 主流程：识别 Mode A or Mode B
    ↓
┌─────────────────────────────┬─────────────────────────────┐
│  Mode A (用户直给)            │  Mode B (意图驱动) ⭐          │
│                              │  source_registry.py 查白名单  │
│                              │  → 展示 URL 清单              │
│                              │  → 用户确认                   │
│                              │  → fetcher.py 抓取（带缓存）   │
└─────────────────────────────┴─────────────────────────────┘
    ↓
Step 1: parse_input.py → 两份（或 N 份）结构化文本
    ↓
Step 2: 加载 references/profile_<file_type>.md → 确定要跑的维度
    ↓
Step 3: diff_engine.py 按 A1-A7 产出定性 diff（B1）
         （N 版情形：两两 diff + 趋势聚合）
    ↓
Step 4: score_model.py 算词频+打分（B2）
    ↓
Step 5: build_charts.py 生成 G1-G6 → charts/
    ↓
Step 6: build_xlsx.py 生成 data.xlsx
    ↓
Step 7: 按 article_style 加载 assets/style_*.md
        → LLM 生成文章正文（C1/C2/C3 融入）
        → build_docx.py 写入 report.docx
    ↓
完成：返回 output/ 路径
```

### 7.3 依赖复用
- **anthropic-skills:docx**：Word 读写复用
- **anthropic-skills:xlsx**：Excel 读写复用
- **anthropic-skills:pdf**：PDF 解析复用
- **Python 库**：`python-docx`、`openpyxl`、`matplotlib`、`plotly`、`pypdf`、`requests`、`beautifulsoup4`

## 8. 技术关键决策

| 决策点 | 选择 | 理由 |
|-------|------|-----|
| 架构 | 主 skill + scripts + references + assets | progressive disclosure，SKILL.md <500 行，按文件类型加载 profile |
| 图表位置 | 独立 `charts/` 文件夹 | 用户明确要求，便于二次创作取用 |
| 文章风格 | 运行时用户指定（3 选 1） | 不同场景诉求不同，不固化 |
| 首发范围 | 仅 govt_work_report | 先打穿一个，验证方法论后复制 |
| 对比方法 v1 范围 | B1 定性 + B2 定量；B3 预留接口 | B3 需要历史数据库，v2 再做 |
| LLM 生成章节 vs 脚本生成 | 文章正文 LLM 生成，图表/表格脚本生成 | 文本创作靠 LLM，结构化计算靠脚本 |
| 复用官方 skill | docx / xlsx / pdf 三者都复用 | 不造轮子，站在巨人肩膀上 |

## 9. Eval 策略

### 9.1 v1 测试用例（放 `evals/evals.json`）

**Mode A 用例**（同组对比跑三种风格，检验风格差异化）：
- **Eval 1**：2024 政府工作报告 vs 2023 政府工作报告 → 投研派
- **Eval 2**：2024 政府工作报告 vs 2023 政府工作报告 → 媒体派
- **Eval 3**：2024 政府工作报告 vs 2023 政府工作报告 → 投资派

**Mode B 用例**（检验信源抓取 + 意图识别）：
- **Eval 4**：prompt = "对比最新两版政府工作报告" → 验证 skill 是否自动找到最新两年 + 展示 URL 清单
- **Eval 5**：prompt = "近三年政府工作报告趋势" → 验证 N=3 趋势分析闭环

### 9.2 评估指标
- **质量层（主观）**：分析师本人 review report.docx 内容、图表合理性
- **结构层（客观）**：
  - 输出目录结构是否完整（report.docx + data.xlsx + charts/6 张 PNG）
  - data.xlsx 4 个 sheet 是否齐全
  - A1-A7 维度是否都有对应差异条目
  - 三种风格文章在长度/句式/术语密度上是否可量化区分

### 9.3 迭代路径
1. **Iteration 1**：跑通 MVP，人工 review 3 个 eval
2. **Iteration 2**：根据反馈调整 profile、调整风格模板
3. **Iteration 3**：benchmark 量化对比（with-skill vs baseline），用 eval-viewer 可视化

## 10. 风险与开放问题

### 10.1 已识别风险
- **R1 政策文本获取的版权/来源**：政府工作报告来自中国政府网（www.gov.cn）公开发布，属于公开资料——无版权风险。但做网页抓取时注意 User-Agent 和 robots.txt。
- **R2 LLM 生成内容的主观倾向**：投资建议（C2）是主观判断，v1 在文章结尾加固定免责声明。
- **R3 PDF 解析质量**：扫描版 PDF（无 OCR 层）会失败——v1 不支持扫描版，明确在 SKILL.md 提示。
- **R4 图表中文字体问题**：matplotlib 默认不支持中文——需要在 `build_charts.py` 中显式指定中文字体（`PingFang SC` / `SimHei`）。
- **R5 Mode B 信源漂移**：政府网站改版会导致 URL 模板失效——`source_registry.py` 需显式版本化、失败报错清晰、自动 fallback 到备源。
- **R6 Mode B 抓取误伤**：防止被 prompt injection 诱导抓非权威源——白名单**硬编码**在 `source_registry.py`，Claude 不通过 LLM 生成 URL，只能从白名单取。
- **R7 Mode B 抓取频率**：同一信源短时间重复抓易被限流——强制走 `cache/` 缓存，同文件同年份只抓一次。
- **R8 Mode B 意图歧义**：用户说"最新两版"，skill 能否准确定位？→ Mode B 抓取前展示 URL 清单给用户确认，用户可修正。
- **R9 N 版趋势分析的组合爆炸**：N=5 时两两 diff 有 10 组——v1 限制 N ≤ 5，且趋势分析采用"滚动相邻对比 + 首末对比"策略，不做全组合。

### 10.2 设计阶段已敲定的次级决策
- **Q1 上一版如何默认**：用户每次显式传两版（v1 不维护历史版本库）
- **Q2 政策强度打分标尺**：放 `profile_govt_work_report.md` 里用关键词锚定（如"大力"=4、"积极"=3、"稳妥"=2）
- **Q3 图表配色**：中性灰为主（#333）+ 红色强调（#c00），避免政治倾向
- **Q4 中文字体**：`build_charts.py` 显式指定 `PingFang SC` / `SimHei` fallback
